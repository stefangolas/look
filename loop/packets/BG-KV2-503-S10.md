Section 1: the claim types — `pub struct ClaimedComponent { seed: Point4,
expected: ComponentKind }` (`ComponentKind`: the landed component
vocabulary of the contact/classifier seams — the tube-chain kind set; if
the landed vocabulary names it differently, use ITS name and note the
spelling in RESULT) and `pub struct TopologyClaim { components:
Vec<ClaimedComponent>, exhaustive: bool, provenance: Provenance }` — the
spec's exact field set. `pub fn certify_claimed(pair: &LeafPair, claim:
&TopologyClaim) -> ClaimVerdict<CertifiedGraph, ClaimRefutation, Refusal>`
over the landed `LeafPair` seam. `ClaimRefutation` names the component
INDEX and the failing predicate (a `String` label of the named predicate —
the predicates are the spec's: tube-chain-via-C2, endpoints-via-C1,
nodes-via-A4.2; the label is the predicate's name, spelled as in this
packet).

Section 2: per-component certification (spec 15 item 1) through the LANDED
seams only: the tube chain via the C2 seam (`engine::c2_certify_tube4`),
endpoints via the C1 seam (`engine::krawczyk_c1`), nodes via 303's A4.2
rules. Any component refuted -> `Disproven(ClaimRefutation)` naming it —
NEVER silently repaired, and the surviving components are NOT certified
into a partial graph (the refutation is total; the spec's item 2 has no
partial-success arm).

Section 3: targeted completeness (spec 15 item 3) — the exhaustive branch.
Tier-1 (`tier1_loop_free`) and Tier-2 (`tier2_start_set`) exclusion run on
the COMPLEMENT of the certified tubes: the packet pre-decides the
mechanical form — the complement is expressed as the Tier-2 domain MINUS
each certified tube's parameter box (box subtraction, the landed IBox
primitives), and Tier-1/Tier-2 run over the resulting boxes. This is one of
the three D4 carve-out sites (fillet-branch isolation and self-intersection
are the other two); `provenance_does_not_discharge_completeness` asserts a
Claimed provenance (or Imported, or Client) does NOT skip item 3 — the
complement exclusion runs regardless. The trusted-provenance mode (spec 15
item 4 / D6): the opt-in skips item 3 but yields a `ClaimedGraph` —
`trusted_provenance_yields_claimed_graph_not_certified` asserts the type,
not a flag. Non-exhaustive claims yield `ClaimedGraph` unconditionally.
