## Problem

Three fillet code paths abort the process on ordinary geometry: a fillet radius
larger than the face curvature, a contact curve running off the trimmed domain,
or a fillet at a chart pole all reach a `.unwrap()` and panic. This violates
house rule **H-1 — no panics on data**. Fillet inputs are untrusted geometry.

This item stops the abort. It does **not** give the right diagnosis —
`RadiusExceedsCurvature` needs real gates, which are out of scope and must not
be invented here.

```rust
pub type Outcome<T> = Result<Certified<T>, Refusal>;

pub enum Refusal {
    Empty,
    UnsupportedEnvelope(EnvelopeCase),
    NumericallyUnresolved { spent: Budget, witness: UnresolvedWitness },
    CompositionMarginExhausted(MarginWitness),
    InputOutsideBackwardBudget(RepairWitness),
    Contradictory(ContradictionWitness),
    Collapsed(Collapse, Certificate),
}

pub enum EnvelopeCase { ChartDegenerate, ReachTooSmall, NonCanonicalCarrier, NonPositiveNurbsWeight }
pub enum UnresolvedWitness { UncertifiedContainment, RootNotIsolated, KrawczykIndeterminate }
```

## Algorithm

Mechanical throughout: `.unwrap()` becomes `?` propagating an `Outcome`.

1. **A1 (4 sites)** → `Refusal::NumericallyUnresolved { spent, witness:
   UnresolvedWitness::ContactCurveNotFound }`.
2. **A2 (2 sites)** → `Refusal::UnsupportedEnvelope(EnvelopeCase::ChartDegenerate)`.
   A singular `[uder, vder, n]` frame **is** a chart degeneracy; that is the
   correct classification, not a placeholder.
3. **A3 (1 site)** → same treatment as A1. Note the inconsistency you are
   repairing: `contact_circle` is already `?`-handled where the initial three
   circles are built, then `.unwrap()`ed on the identical call inside the
   refinement closure.

### Two decisions already made for you — implement them, do not re-litigate

**(a) Add one variant** to `UnresolvedWitness` in
`vendor/truck/truck-base/src/evidence.rs`:

```rust
    /// The fillet contact curve could not be located on the adjacent edge
    /// within budget (BG-S0-002).

```

No existing variant fits, and reusing `UncertifiedContainment` would be a
wrong-but-confident label. This is the only edit permitted in that file.

**(b) The signatures change from `Option` to `Outcome`.** `simple_fillet`,
`create_pcurve_edge` and `approx_rolling_ball_fillet` currently return
`Option<_>`. `?` on an `Outcome` cannot compile inside an `Option`-returning
function, so the return types become `Outcome<_>` and the call sites follow.
This is required by **H-2 — every fallible operation returns `Outcome<T>`,
never `Option` or a bare `Result`. `None` is not a diagnosis.**

Known call sites, all inside `write_allow`: `fillet/experiment.rs` (8),
`fillet/mod.rs` itself (5), `tests/fillet.rs` (2), `tests/af_surface.rs` (1).
A call site that only asks "did it work" becomes `.is_ok()`; one that needs the
value uses `?` or matches on the `Refusal`.

Where a `Budget` is needed for `spent` and none is threaded yet, use
`Budget::default()` and mark the site `// TODO(BG-NUM-001): thread the real
budget`. Do **not** add a budget parameter to these signatures — that is
BG-NUM-001's job and doing it here would collide with a later packet.
