Section 1: `pub struct SpineFrameSweep` in `constructive/sweep_surface.rs`
— the spec 5.10 type: `recipe: SpineFrameRecipe<Spine, ProfileLaw,
FrameLaw>` (the four spec fields live inside the landed recipe; do NOT
restate them flat), plus `transform: Matrix4` as the SWEEP-LEVEL placement.
Refusing constructor (`try_new`-shaped, `ConstructError`-carrying) reusing
the landed recipe validators; no numeric evaluation here — realization
stays in the landed evaluator path. The enum variant
`Surface::SpineFrameSurface` in `canonical.rs` switches its payload from
`SpineFrameSurface<Box<Curve>>` to `SpineFrameSweep`. The variant NAME does
not change — the payload type changes.

Section 2: window views derive, never store. The per-profile-edge window
data (`s0/s1/v0/v1`) that used to live in the variant payload moves to a
derived view (`spine_frame.rs` keeps the realization-side decorator, now
constructed FROM a sweep + window, not stored IN the enum). The landed
realization semantics are unchanged: same evaluators, same validation, same
outputs — only the storage boundary moves. `sweep_transform_is_sweep_level`
asserts the sweep-level transform equals what the landed B-rep constructor
set for its fixtures (if the landed constructor ever sets DIFFERENT
transforms on two faces of one sweep, that is stop condition 2).

Section 3: the typed-refusal carry (`spine_sweep.rs` A3): `refuse` currently
DROPS the `ConstructError` detail. Rewrite the mapping as an explicit
per-variant `match` over `ConstructError` (every variant named, NO catch-all
arm) mapping to its honest `EnvelopeCase`; `refusal_mapping_is_total_no_
catch_all` asserts the match is total by construction (the compiler proves
it; the test asserts the no-catch-all property textually via the match
exhausting without a wildcard arm). If a variant has no honest envelope
case, that is stop condition 3 — do not invent one.
